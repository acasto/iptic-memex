* Editing files with shell tools (complements the 'file' tool):
  + The 'file' tool is preferred for reading and for writing/patching whole or partial files; it also handles pdf/docx/xlsx/images/audio.
  + Use the 'cmd' tools below for surgical edits in long files, bulk transforms, or structured-data queries.

* TOOLKIT (installed in this container):
  - Search/discovery: rg (ripgrep), fd
  - Text edits: sd (simple single-line replaces only), sponge (safe in-place pipeline writes: `... | sponge file`)
  - Structured data: jq (JSON), yq (YAML), dasel (TOML/CSV/XML), xmlstarlet (XML), mlr (Miller, CSV/TSV)
  - Code transforms: sg -lang <lang> -p '<pattern>' (add --rewrite to apply fixes), semgrep --autofix
  - Lint/fix: ruff --fix (Python), eslint --fix (JavaScript)
  - Patches: git apply --check, then git apply --3way; patch

* TIERED EDITING STRATEGY:
  1. Diff/patch -> git apply --check, then git apply --3way
  2. Code transforms -> sg --rewrite or semgrep --autofix
  3. Structured data -> jq/yq/dasel/xmlstarlet, piped through sponge for in-place updates
  4. Simple text replacements -> sd 'pattern' 'replacement' file
  5. Multi-line insertions -> here-doc + sed: `cat << 'EOF' > /tmp/ins.ext` then `sed -i '/pattern/r /tmp/ins.ext' file`
  6. Last resort -> rewrite the file with the file tool

* CONTAINER NOTES:
  - Ubuntu 24.04 (arm64). /workspace is the project mount (read-write); /tmp is writable scratch space.
  - Verify edits landed: grep -A3 -B3 or head/tail afterward.
  - Combine multi-step operations in a single cmd call when using temp files.
  - For syntax-aware searches, default to sg over grep/rg unless explicitly requested plain text.
  - If escaping gets complex (nested quotes), switch to the here-doc approach immediately.
  - sd is for simple replacements only; use the file tool's patch mode for multiline or complex patterns.
